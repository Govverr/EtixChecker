## 🛠 Зафиксированные ошибки и решения:

### [2026-08-24] Ошибка загрузки DLL для парсера `lxml` в Windows (`ImportError: DLL load failed while importing etree`)
- **Контекст / Ошибка:** При вызове BeautifulSoup с парсером `'lxml'` в среде Windows с Python 3.11/3.12 происходило падение с ошибкой `ImportError: DLL load failed while importing etree: The specified module could not be found.`
- **Причина:** Бинарный пакет `lxml` на Windows может требовать внешние C-рантаймы libxml2/libxslt, отсутствующие в базовой системе.
- **Решение:** В `BeautifulSoup(html, "html.parser")` переключиться на стандартный встроенный парсер Python `html.parser`, который не зависит от C-библиотек и работает быстро и стабильно на всех ОС.

### [2026-08-24] Перебор суточной квоты ордеров (Over-quota drift) за несколько ночных циклов
- **Контекст / Ошибка:** При целевом лимите `target_orders = 12` бот за 3-4 цикла набирал 30-40 ордеров за ночь, так как воспринимал лимит как ограничение на *один цикл*, а не на *всю рабочую сессию*.
- **Причина:** Отсутствовал кумулятивный учет захваченных ордеров в рамках текущей сессии (`SessionModel`) и расчет `remaining_quota = max(0, target - assigned)` перед каждым циклом.
- **Решение:** Введена таблица `bot_sessions` (`SessionModel` / `SessionRepository`). В каждом цикле рассчитывается остаток квоты `remaining_quota`. Как только `target_orders_assigned >= target_orders`, бот автоматически завершает работу (`is_running = False`) с формированием итогового отчета.

### [2026-08-24] Блокировка SQLite (`sqlite3.OperationalError: database is locked`) при параллельных async операциях и отмене задач
- **Контекст / Ошибка:** При параллельном выполнении cron-проверок (автостоп) и рабочего цикла скрапинга вызовы `UPDATE` в SQLite падали с `database is locked`.
- **Причина:** Отсутствие постоянного `PRAGMA busy_timeout` для новых подключений SQLAlchemy connection pool, а также удержание активных транзакций БД во время длительных сетевых HTTP-запросов к CRM.
- **Решение:** 
  1. Добавлен слушатель событий `@event.listens_for(engine.sync_engine, "connect")`, выставляющий `PRAGMA journal_mode=WAL` и `PRAGMA busy_timeout=15000` на каждом соединении.
  2. Сессии БД открываются кратковременно только для запросов/обновлений и не удерживаются во время внешних HTTP-запросов.
  3. В `Orchestrator.stop()` рабочий процесс `_worker_task` отменяется и ожидается ДО открытия сессии финализации.

### [2026-08-25] Задвоение строк в разметке BetterTickets ACP (`InProgress` 19 шт. вместо 10 шт.)
- **Контекст / Ошибка:** В отчете бота отображалось `Всего ордеров в InProgress: 19 шт.`, хотя в CRM по фильтру было ровно 10 строк.
- **Причина:** В HTML-таблице BetterTickets каждый ордер может иметь дочернюю строку раскрытия деталей (`<tr class="n-ui-acp-grid-row-detail ...">`), также имеющую атрибут `data-entity-id`. Парсер без дедупликации считывал каждую строку дважды.
- **Решение:** 
  1. В `parse_orders_from_html` добавлен фильтр дочерних классов (`sub-row`, `row-detail`, `detail`, `collapse`).
  2. Введена строгая дедупликация по `order_id` через `seen_order_ids: set[str]`.

### [2026-08-25] Подхват старой зависшей сессии при повторном запуске бота (цель 15 вместо 12, длительность 5 ч)
- **Контекст / Ошибка:** После изменения цели на `12` и перезапуска бота в отчете отображалось `Целевых ордеров набрано: 12 / 15`, `Tanglewood: 2 шт.` (хотя был 1), и длительность `5 ч 34 мин` вместо 1 минуты.
- **Причина:** При ручном перезапуске или отмене процесса старая запись `SessionModel` в БД оставалась со статусом `ACTIVE` (со старой целью 15, старым временем старта и старыми набранными ID), и `start()` ошибочно переиспользовал её вместо создания новой.
- **Решение:** 
  1. Метод `Orchestrator.start()` теперь всегда принудительно создает свежую сессию (`SessionRepository.create_session`), автоматически закрывая любые предыдущие незавершенные сессии.
  2. При изменении `target_orders` в настройках Telegram параметр автоматически синхронизируется с текущей активной сессией.
  3. Улучшено форматирование коротких сессий (< 1 минуты) с отображением точных секунд.

### [2026-08-27] Ошибка `NameError: name 'UserService' is not defined` при ручной синхронизации инвентаря
- **Контекст / Ошибка:** При нажатии кнопки «Обновить сейчас» в меню On-Hand инвентаря возникало исключение `NameError: name 'UserService' is not defined`.
- **Причина:** В модуле `bot/handlers/inventory.py` в функции `handle_manual_sync` вызывался `UserService.get_by_id(...)`, однако импорт `from services.user.user_service import UserService` отсутствовал в шапке файла.
- **Решение:** Добавлен явный импорт `UserService` в `bot/handlers/inventory.py`. Проверены все остальные файлы обработчиков на наличие корректных импортов.

### [2026-08-27] Ошибка HTTP 404 при загрузке страницы авторизации (`Failed to load login page: HTTP 404`)
- **Контекст / Ошибка:** При попытке авторизации в CRM BetterTickets клиент падал с `CRMAuthError: Failed to load login page: HTTP 404`.
- **Причина:** В клиенте был захардкожен URL `/Identity/Account/Login`, тогда как в рабочей версии BetterTickets ACP путь авторизации расположен по адресу `/Account/Login` (или `/account/login`), а поля ввода называются `Login` и `Password` (вместо `Input.Email` и `Input.Password`).
- **Решение:** 
  1. В `services/crm/parser.py` добавлена функция `parse_login_form`, динамически определяющая URL формы, CSRF токен `__RequestVerificationToken` и точные имена полей логина, пароля и RememberMe.
  2. В `services/crm/client.py` добавлен перебор URL-кандидатов (`/Account/Login`, `/account/login`, `/Identity/Account/Login`, `/`) с автоматическим обнаружением формы и отправкой данных на актуальный эндпоинт.

### [2026-08-27] Сбор всей базы On-Hand (4001 шт.) вместо билетов конкретного сотрудника
- **Контекст / Ошибка:** При синхронизации инвентаря для пользователя (например, `Krosin@vicecitymail.com` или `Krosin Kovalchuk`) бот парсил 4001 билет (весь инвентарь CRM), игнорируя фильтрацию по сотруднику.
- **Причина:** BetterTickets CRM в фильтрах таблицы On-Hand ожидает числовой идентификатор пользователя в параметрах `PurchasedById` и `OfferedById` (например, `PurchasedById=26`). Передача текстового `PurchasedBy=Krosin...` игнорировалась бэкендом BetterTickets, возвращая общий список без фильтра.
- **Решение:** 
  1. В `BetterTicketsClient` добавлен метод `resolve_crm_user_id(crm_name)`, запрашивающий autocomplete эндпоинт BetterTickets (`/acp/user/autocomplete-values`) с параметром `qs` и кэширующий найденный числовой ID сотрудника.
  2. В `fetch_on_hand_by_purchased` и `fetch_on_hand_by_offered` параметры запроса переключены на `PurchasedById=<id>` и `OfferedById=<id>`.
  3. В `SyncService.sync_user_inventory` добавлена автоматическая очистка билетов пользователя, которые не возвращаются фильтром CRM (удаление ошибочно загруженных ранее билетов).

### [2026-08-27] Задвоение строк On-Hand из-за неигнорируемых строк `n-ui-drawer` (53 шт. $\to$ 106 шт.)
- **Контекст / Ошибка:** При парсинге страницы с 53 билетами в CRM парсер возвращал 106 билетов, а в списке инвентаря появлялись фантомные билеты с названием `(Detailed Pricing Notes Order Attachments Logs...)`.
- **Причина:** В HTML-таблице On-Hand BetterTickets под каждой основной строкой билета следует скрытая строка деталей с классом `<tr class="n-ui-drawer">`, которая не фильтровалась парсером и считывалась как отдельный билет.
- **Решение:** 
  1. В `services/crm/parser.py` в список игнорируемых классов строк добавлены `"drawer"` и `"n-ui-drawer"`.
  2. Добавлена проверка на минимальное количество ячеек `len(cells) >= 4` и валидный формат UID.
  3. Обновлены тексты тегов: `[O]` $\to$ «Предложен вами», `[P + O]` $\to$ «Куплен и предложен вами».

### [2026-08-27] Невозможность резолва CRM ID для составных имен (например, `Сергій#0908 Remaiev (Sergii@vicecitymail.com)`) $\to$ найдено 0 билетов
- **Контекст / Ошибка:** При синхронизации для нового пользователя `Валеев` с CRM-именем `Сергій#0908 Remaiev (Sergii@vicecitymail.com)` бот выдавал ошибку `Could not resolve CRM user ID` и парсил 0 билетов.
- **Причина:** В автокомплит CRM BetterTickets отправлялась вся сырая строка целиком со спецсимволами `#0908` и скобками `(...)`, что приводило к пустому ответу от бэкенда BetterTickets.
- **Решение:** 
  1. В `find_crm_user` (`services/crm/client.py`) внедрен интеллектуальный экстрактор поисковых запросов (извлечение чистого email из скобок `(...)`, извлечение чистых слов имени/фамилии без спецсимволов).
  2. Обновлены формулировки тегов в статистике: `[O]` $\to$ «Предложено вами», `[P + O]` $\to$ «Куплены и предложено вами».

### [2026-09-09] Искажение кириллицы/Unicode при распаковке файлов локализации Apple `.strings`
- **Контекст / Ошибка:** При наличии в `.pkpass` файла локализации `pass.strings` со строками на русском языке (`"ORG_NAME_KEY" = "Большой Театр";`) тест падал с `AssertionError: assert '\xd0\\x91\xd0\xbe\xd0\xbb...' == 'Большой Театр'`.
- **Причина:** Использование цепочки `val.encode().decode("unicode-escape")` для снятия экранирования ошибочно декодировало байты UTF-8 как latin-1 escape-символы.
- **Решение:** Введена функция `_clean_apple_string`, которая точечно заменяет `\uXXXX` через `chr(int(..., 16))` и базовые экранирования (`\"`, `\\`, `\n`), сохраняя многобайтовые UTF-8 символы нетронутыми.

### [2026-09-09] Сбой установки Python 3.11 через WiX Burn Bundle с кодом 50 (`0x80070032: Failed to elevate`)
- **Контекст / Ошибка:** При установке Python 3.11 для текущего пользователя (`InstallAllUsers=0`) процесс завершался с кодом 50.
- **Причина:** Пакет лаунчера `launcher_AllUsers` по умолчанию пытался установиться системно и запросить повышение прав UAC, что в автоматическом режиме приводило к отказу `0x80070032`.
- **Решение:** В аргументы запуска инсталлятора добавлен флаг `Include_launcher=0` (`InstallAllUsers=0 Include_launcher=0 PrependPath=1 /passive`), что гарантирует установку в область пользователя без запросов UAC.

### [2026-09-09] Несоответствие даты и времени билета из-за `relevantDate` (UTC смещение вместо локального времени)
- **Контекст / Ошибка:** На сгенерированном билете в правом верхнем углу отображалось `3:00 AM Sep 6, 2026`, тогда как на iPhone билет отображал `8:00 PM SEP 5, 2026`.
- **Причина:** В стандарте Apple Wallet поле `pass_data["relevantDate"]` служит для активации карточки на экране блокировки iOS и всегда хранится в UTC (`2026-09-06T03:00:00Z`). Парсер ошибочно отдавал приоритет `relevantDate`, затирая реальные локальные данные из `headerFields`.
- **Решение:**
  1. `headerFields` сделан основным источником истины для шапки билета, а `relevantDate` переведен в резервный фоллбек.
  2. В `_extract_iso_or_text_date` сохраняется исходное локальное время без конвертации в UTC.
  3. В шаблоне `ticket_sheet.html` правый верхний угол рендерит `field.label` сверху (мелким шрифтом) и `field.value` снизу (крупным шрифтом), в точности как на iOS.

### [2026-09-09] Генерация Micro QR вместо стандартного QR-кода (визуальное отличие и риск несканирования)
- **Контекст / Ошибка:** Сгенерированный ботом QR-код визуально отличался от отображаемого в приложении Apple Wallet на iPhone (в коде была только 1 большая угловая метка вместо 3).
- **Причина:** Функция `segno.make()` для коротких строк полезной нагрузки по умолчанию генерирует компактный `Micro QR (M4)`. Apple Wallet (PassKit) в iOS использует исключительно полноразмерный стандартный QR-код (`ISO/IEC 18004`) с 3 угловыми метками (`Finder Patterns`).
- **Решение:** В `_generate_qr_data_uri` вызов `segno.make()` заменен на `segno.make_qr(..., error="M", encoding=encoding)`. Это исключает генерацию Micro QR и гарантирует 100% пиксельное совпадение с экраном iPhone и 100% считываемость любыми профессиональными турникетами и лазерными/оптическими 2D-сканерами на площадках.

### [2026-09-10] Затенение типов полей в Pydantic v2 (`Input should be None [type=none_required]`)
- **Контекст / Ошибка:** При валидации Pydantic модели `EventItem` падала ошибка `1 validation error for EventItem: EventLocation: Input should be None [type=none_required, input_value=EventLocation(...)]`.
- **Причина:** Имя атрибута в классе совпадало с именем типа: `EventLocation: Optional[EventLocation] = None`. Во время компиляции класса имя типа затеняется именем поля в локальной области видимости, из-за чего аннотация типа разрешается некорректно.
- **Решение:** Избегать совпадения имени атрибута и имени класса типа. Класс переименован в `EventLocationData`, а поле типизировано как `EventLocation: Optional[EventLocationData] = None`.

### [2026-09-14] Ложное закрытие окон на специфических URL Etix, коллизии многопользовательского режима и недотягивание слайдера
- **Контекст / Ошибка:** 
  1. При проверке некоторых ссылок (McDonald Theatre, Cat's Cradle) открывалось первое окно и чекер немедленно завершал работу со статусом `BLOCKED` или `FAILED`.
  2. При одновременной работе нескольких коллег в AdsPower чекер закрывал чужие браузеры через `stop_all_active_browsers()`.
  3. Ползунок слайдер-капчи DataDome иногда выдавал ошибку сайта «протяните до конца».
- **Причина:** 
  1. На специфических площадках Etix выполняет редирект (добавляет `?partner_id=...` или переводит на брендированный домен, например `cascadetickets.com`), из-за чего жесткое условие `target_path not in curr_url` вызывало 3 циклические перезагрузки, а модальные окна площадок ("I Agree / All Ages") не закрывались.
  2. Вызов `client.stop_all_active_browsers()` не фильтровал профили по владельцу текущей сессии.
  3. Расчет `end_x` для слайдера вычитал 1-3 px от ширины трека, из-за чего ползунок останавливался за 3-5 px до аппаратного сенсора.
- **Решение:** 
  1. Внедрен `extract_performance_id`, выполняющий матчинг по числовому ID события вне зависимости от редиректов и параметров. Расширен `close_blocking_popups` для закрытия любых дисклеймеров площадок.
  2. Внедрен строгий аудит владения профилями: перед стартом опрашивается `/api/v1/browser/active`, занятые профили помечаются `BUSY_EXTERNAL` и исключаются. При нехватке свободных профилей старт блокируется с предупреждением. В `cdp_pool.close_all()` закрываются строго профили текущей сессии.
  3. Откалибрована координата `end_x` с физическим упором в правый буфер и добавлена финальная фаза микро-фиксации (Lock-in phase).
