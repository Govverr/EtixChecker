## 🎯 1. О проекте: Назначение и Архитектура

**Etix Checker 2026 (AdsPower CDP Edition)** — высокопроизводительный асинхронный инструмент для мониторинга доступности, инвентаря и пакетного резервирования билетов на платформе **Etix**.

### Ключевая концепция:
- Работает через антидетект-браузер **AdsPower** (SunBrowser) по протоколу **Playwright CDP (Chrome DevTools Protocol)**.
- Использует пул изолированных профилей с уникальными аппаратными цифровыми отпечатками железа и выделенными резидентскими / мобильными прокси (в группе `Inventory Etix (DO NOT TOUCH)`).
- Поддерживает одновременную работу до 12 активных профилей и горячую замену из пула резервных профилей (80+ профилей).
- Полностью написан на асинхронном Python 3.10+ с модульной структурой (`src/`).

## ⚙️ 3. Ключевые бизнес-правила и технические решения

### 1. Поддержка выпадающих списков (Material-UI + Classic Select):
- Современные страницы Etix используют кастомные **Material-UI (MUI React v5)** селекторы: `div[role="combobox"]` / `.MuiSelect-select`. Внутри это `<div>` со всплывающим меню `li[role="option"]`.
- Старые страницы Etix используют стандартные HTML-теги `<select>`.
- Модуль [`src/etix/cart_handler.py`](file:///d:/etixSetupTest/src/etix/cart_handler.py) поддерживает оба варианта.

### 2. Индексация `ticket_index` (1-based):
- В файле `shows.csv` параметр `ticket_index` задается в **1-based** индексации:
  - `ticket_index = 1` $\rightarrow$ 1-я категория билетов на странице (индекс 0 в коде).
  - `ticket_index = 2` $\rightarrow$ 2-я категория билетов на странице (индекс 1 в коде).

### 3. Динамический расчет профилей и рандомизация пула:
- Чекер вычисляет число необходимых профилей: $\text{needed} = \lceil\text{target\_total} / \text{max\_per\_order}\rceil$.
- Если цель 12 билетов при лимите 4 $\rightarrow$ чекер запускает ровно **3 профиля** (а не все 12).
- Профили выбираются **случайным образом (`random.sample`)** из активного пула AdsPower для равномерного расхода прокси.

### 4. Конвейер случайных задержек (Staggered Pipeline ~45 сек на 12 профилей):
- Все действия разнесены во времени случайными сдвигами:
  - **Навигация:** сдвиг `600–1100 мс` между профилями.
  - **Пауза после выбора билета:** `500–900 мс` (для синхронизации React/MUI state).
  - **Клик «Add Tickets»:** сдвиг `1000–1800 мс` между профилями.
  - **Удержание брони:** `4.0 сек`.
  - **Очистка корзин:** сдвиг `600–1000 мс` между профилями (через кнопку `Clear Shopping Cart`).
- Зафиксированы безопасные нижние границы `MIN_SAFE_DELAYS`, ниже которых пользователю запрещено ставить задержки.

### 5. 3-этапная система обхода DataDome и капчи:
1. **Шаг 1 (Drag & Drop):** Плавный сдвиг слайдера по кривой Безье с естественным вертикальным дрожанием мыши ($\pm 1 - 3\text{px}$).
2. **Шаг 2 (Cookie Reset):** Очистка куки через CDP (`context.clear_cookies()`), закрытие вкладки и открытие чистой новой вкладки.
3. **Шаг 3 (Hot-Swap):** Мгновенная замена упавшего профиля на свободный резервный профиль (из 80+ резервных), установка ему через AdsPower API (`POST /api/v1/user/update`) чистого прокси из `good_proxies.txt` и продолжение работы.

### 6. Обработка мертвых / истекших прокси:
- Таймаут навигации: **18 секунд** (`nav_timeout = 18000`).
- Перехват сетевых ошибок Chrome (`ERR_PROXY_...`, `ERR_CONNECTION_...`, `chrome-error://`) и мгновенный запуск Hot-Swap.
- Пометка плохих прокси действует **строго в рамках текущей сессии проверки** (не навсегда).

### 7. Синхронизация `good_proxies` без сервера:
- Модуль [`src/storage/proxy_sync.py`](file:///d:/etixSetupTest/src/storage/proxy_sync.py) при запуске подтягивает проверенные прокси по прямой ссылке из GitHub Raw / Secret Gist (`GOOD_PROXIES_SYNC_URL`) и объединяет с локальным файлом.

### 8. Гарантированное закрытие профилей AdsPower:
- При завершении проверки или ошибке метод `cdp_pool.close_all()` гарантированно останавливает все открытые окна AdsPower через `/api/v1/browser/stop`.

## 🎯 5. Текущий статус и План дальнейшей разработки

### ✅ Что уже реализовано:
1. **Строгий барьер готовности воркеров (Readiness Barrier):** Гарантия того, что 100% задействованных профилей открыли страницу события, прошли капчу/санитарию и готовы к одновременному набору корзин.
2. **1-Click Updater в GUI:** Безопасное обновление программы с GitHub без необходимости установки Git у пользователя и с жесткой защитой пользовательских файлов (`.env`, `shows.csv`, `good_proxies.txt`, бэкапы).
3. **Checkbox-выбор событий в GUI:** Выборочный запуск проверки для отмеченных пользователем мероприятий, кнопки «Выбрать все» / «Снять все», динамический пересчет метрик дашборда.
4. **Всеконтекстный обход DataDome Slider:** Мультифреймовый детектор (сканирование всех `page.frames`, включая `geo.captcha-delivery.com`), 3-фазная траектория Безье с микродрожанием мыши $Y \pm 1-3\text{px}$, биометрическими паузами и бесшовным возвратом к событию.
